Kit v1.0.0. Ground checkout: `/path/to/my-expo-app` (`git rev-parse --show-toplevel`).
Every value carries its evidence: a file in the ground checkout, a command and its output, or "asked Q#". This is a
fictional example project: the files cited below are illustrative and exist in no real repository.

## Stack

- Area: Mobile (asked Q1; `package.json` lists `expo` and `react-native`).
- Stack: Expo / React Native, status battle-tested (asked Q2; Appendix C detection: `app.config.ts` exports the Expo
  config, `metro.config.js` uses `expo/metro-config`).
- App: a reading-list app (books, notes, offline reading, sync).
- Native folders: Expo CNG / prebuild. `ios/` and `android/` are gitignored (`.gitignore`) and generated by
  `npx expo prebuild` (`package.json` script `prebuild`).
- Dev client: `expo-dev-client` (`package.json`).
- Language: TypeScript (`tsconfig.json`).
- State and data: Redux Toolkit store in `src/store/`; server data through RTK Query API slices in `src/store/api/`;
  persisted slices (redux-persist on MMKV) migrated in `src/store/migrations.ts` (`CONTRIBUTING.md`, "State").

## Package manager

- npm; lockfile `package-lock.json` (`CONTRIBUTING.md`, "Setup").
- Node: pinned in `.node-version`; CI uses it (`.github/workflows/ci.yml`, `node-version-file: .node-version`).
- No `Gemfile`: CocoaPods comes from the machine, and `npx expo prebuild` runs `pod install`.

## Policies (Q4)

- Tracker: GitHub Issues, key pattern `GH-[0-9]+` (issue #123 is floor key `GH-123`; asked Q4). Each chosen preset's
  CLI reads an issue read-only with `gh issue view <num> --comments` (checked in Phase 2: `gh auth status`). Helm runs
  on Codex.
- Signing: yes (asked Q4). `git config --show-origin --get commit.gpgsign` → `file:.git/config true` (set by the
  repo); key `user.signingkey` → `EXAMPLEKEY1234` (confirmed in Q4; a key ID, never a secret). Recipe: a gpg loopback
  wrapper that reads the passphrase from the env var `GPG_PASSPHRASE` (see Vault and RUNBOOK "Signing"). The
  passphrase is never printed. Verify with `git log -1 --format=%G?` → `G`.
- AI attribution: forbidden in commits, PRs and issue comments (asked Q4); the PR template has no AI-disclosure
  checkbox.
- Language of commits, PRs and issue comments: English (asked Q4).
- Approvals: the human approves every push, merge and issue comment, through the Maestro (asked Q4).
- `CODEX_PRETRUST=1` (asked Q4).

## Models (Q3)

- Presets: "Claude Code" and "Codex" (asked Q3, chosen from `maestri preset list`).
- Codex (provider OpenAI, quota plenty): `gpt-6.1-sol` (strongest); fallback `gpt-6-astra`.
- Claude Code (provider Anthropic, quota limited): `claude-opus-5-5` (strongest), `claude-fable-5-1`,
  `claude-sonnet-5-5`. Fallback to another provider's model: no; Claude Code roles fall back within Claude Code, so
  every gate keeps its family on fallback (asked Q3).
- Strongest overall: `claude-opus-5-5`; best coding per cost: `gpt-6.1-sol` (asked Q3).
- Allocation (Phase 3):
  - PLANNER, BUILDER and REVIEWER_A → Codex `gpt-6.1-sol`;
  - GATE → Claude Code `claude-opus-5-5`;
  - SHIPPER → Codex `gpt-6-astra` (cheapest: quota pressure first, and Codex has plenty while Claude Code is
    limited; then price, and `gpt-6-astra` costs less than `gpt-6.1-sol`);
  - ARBITER → Claude Code `claude-opus-5-5`.
- GATE is in a different family from PLANNER and BUILDER, and REVIEWER_A is in a different family from Onyx, so there
  is no independence warning. See `MODEL_MAP.tsv`.
